## 自适应与间距：必需布局检查

适用于页面工具栏、搜索区、筛选/排序操作组等组合布局。先确定项目确认的边缘关系和间距 token，再检查真实浏览器；不能仅凭源码包含 flex、token 或构建成功判定通过。

- **自适应宽度**：需要占满内容区的组合区域共用左右边缘。搜索等可伸缩控件使用剩余空间并能缩小，操作按钮保留可用尺寸；不能因无依据的固定 width/max-width 留下空档。窄屏换行后，各行应占满的区域仍对齐且无水平溢出。
- **同类间距**：同类相邻操作组采用同一间距 token，比较实际控件边缘距离，包括换行后的行间距。明确区分元素间 gap、元素内 padding 和焦点环；不以可见焦点环边缘代替控件边界。不同功能层级的间距可以不同，必须符合确认的规则，不把某个项目的 16px 强加给所有项目。
- **状态覆盖**：桌面/窄屏 × 附属操作按钮显示/隐藏；有清空、重置、错误提示等影响布局的状态时覆盖对应变化。以 DOM getBoundingClientRect 记录实际视口、相邻边缘、差值和溢出，并保存截图。应相等的边缘/间距允许最多 1 CSS px 的舍入偏差，超出需修复或重新确认有依据的例外。
- **交付阻塞**：把适用的自适应对齐、间距一致检查写入 `.design-workflow/delivery.json` 的必需 visual/interaction criteria，声明 pages、desktop/narrow viewports、相应 states，并附测量与截图证据。不得删除失败项、降为可选或用旧截图补新通过；后续受影响源码变化必须重验。无适用组合布局时记录原因，不虚构测量。
