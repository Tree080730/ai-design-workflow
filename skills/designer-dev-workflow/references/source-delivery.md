# 源码交付契约

用于页面、组件及设计系统建设的正式实现与交付；需求范围以用户确认的 Spec 为准。

## 三阶段完成范围

设计依据与约束阶段交付确认规则和 Spec；设计系统阶段交付真实样式/组件及 Gallery；业务阶段交付页面/路由/交互与同步资产。完整业务需求不能以只完成前两阶段为结束。只要求设计系统时不额外实现业务页面，但源码和 Gallery 仍必需。

## 交付内容

| 范围 | 必需源码及接入 |
|---|---|
| 页面需求 | 页面/布局源码、适用的交互与状态实现、真实入口或路由、所依赖的组件与样式 |
| 组件需求 | 可编辑组件实现、适用变体/状态、真实调用位置或 Gallery 展示；复用现有组件时登记真实来源 |
| 设计系统建设 | 唯一可执行 token/样式来源及真实接入、当前需要的组件实现、可运行 Gallery 源码 |
| 0→1 | 已确认技术栈的工程骨架、运行入口、必要依赖与配置，以及当前需求涉及的上述内容；最小路径同样必需 |

沿用项目框架与工具链。不固定目录或要求 React/JSON→CSS；CSS 变量、现有主题管线等均可作为实际运行来源。只实现当前需求需要的资产，复用或导入第三方组件时说明依赖与映射，不要求复制第三方库源码。

## 判定

- 文件写入目标项目并可编辑；不能只存在于聊天、临时目录、截图或编译产物中。
- 检查文件内容与入口接入，空文件、TODO 骨架、未替换模板、只有类型声明和文档路径不算对应功能的完成实现。
- tokens 实际影响运行样式，组件由页面/Gallery 引用，页面接入口/路由；不得用孤立演示或副本证明正式实现已完成。
- 明确安装/启动/构建方式及执行结果。运行未执行或环境受限时记录未验证，不能伪造通过。
- Gallery 可以使用标注的本地模拟数据；业务需求中的真实数据接入按确认范围实现，未接入的业务能力仍标为未完成。
- 未取得方案确认时停留在方案阶段并说明等待确认，不能因此将任务标为完成。

## 交付记录

按实际文件列出：源码路径、职责、复用来源、运行入口/引用位置、规范映射。记录可复现命令、实际检查结果、未实现项和未验证项。缺少必需源码或入口不通属于未完成；已有实现但无法在当前环境执行属于运行未验证。

这些是宿主需要核验的交付条件，不由 CLI 文件数量或结构健康自动保证。
