# RULES.md 模板

`RULES.md` 保存项目长期有效、跨模块的约束。具体视觉数值和单组件细节应放在 `design-system/`，临时需求应放在本次 spec，不应进入 RULES。

```markdown
# 项目开发规则

## 1. 项目边界

- 目标平台：
- 支持环境：
- 事实来源：源码、配置和设计系统；文档冲突时先核验。

## 2. 强制原则

1. 修改前读取现有实现和上下游。
2. 优先复用现有 token、组件和页面模式。
3. 需求或交互不明确时先确认，不自行补充产品决策。
4. 共享组件、全局 token、路由、状态底座和新增依赖属于高影响变更，实施前确认。
5. 新增或修改设计资产后同步设计系统文档、索引和预览。

## 3. 文件与命名

- 页面目录与命名：
- 通用组件目录与命名：
- 业务组件目录与命名：

## 4. 实现规则

- 样式优先使用语义 token；新增裸值必须说明原因。
- 预览代码不得包含真实 API 或业务副作用。
- 临时路由和临时文件不得进入正式交付。
- 加载、空、错误、禁用和极端数据按需求覆盖。

## 5. 验证与交付

- 必跑命令：
- 浏览器验证入口：
- 设计系统同步方式：
- 交付文档位置：

## 6. 优先级

- P0：违反会破坏构建、数据、全局体验或长期维护，必须修复。
- P1：重要一致性要求，应在本次交付完成。
- P2：优化建议，可记录后续处理。

## 7. 索引

- 开发路径：`DEV-WORKFLOW.md`
- 项目映射：`.design-workflow/project-adapter.json`
- 设计系统：`design-system/README.md`
```

更新规则：先提出“新增/修改/删除内容、来源和影响”，得到确认后写入。自动扫描只能提出候选规则，不能自动把一次性偏好升级为长期约束。
