# E2E 基准

只在路由、异步恢复、跨页状态、持久化、可逆操作或关键业务流程变化时使用。优先复用项目已有框架和命令；本参考不要求统一使用 Playwright。

## 最小闭环

按需求选择适用项，不机械生成全部用例：

1. 入口可达，并能完成主要成功路径。
2. 加载失败后展示可理解的状态；重试必须验证恢复结果，而不只是按钮存在。
3. 持久化状态在刷新或重新进入后仍正确。
4. 可逆操作能够撤销，并到达正确的最终状态或空状态。
5. 未知资源和未知路由提供恢复入口。
6. 代表性桌面与窄屏下无意外溢出；需要对齐的模块共享预期轨道。
7. 关键控件通过实际浏览器的可访问名称和 role 操作，不根据截图或另一工具的角色映射猜测选择器。

## 确定性

- 测试数据、延迟、失败和恢复必须可复现，避免依赖真实网络或随机结果。
- 每条用例独立初始化状态；清理 localStorage、数据库夹具或缓存时只操作测试范围。
- 等待用户可观察的结果，不使用固定长时间 sleep 代替状态断言。

## 运行时准备

- 安装测试包不代表浏览器运行时已经可用。首次运行前按项目所选框架显式安装或核验运行时。
- 以 Playwright 为例，可按项目需要执行 `npx playwright install chromium`；CI 应缓存或显式安装对应浏览器。
- 浏览器二进制、trace、截图和报告属于本地/CI 产物，不应默认提交仓库。
- Harness 不自动下载浏览器，也不擅自新增测试依赖。

## 结果记录

交付记录应区分：人工浏览器验证、自动化 E2E、运行项目/视口、用例数量、失败与修正、仍未覆盖的风险。
