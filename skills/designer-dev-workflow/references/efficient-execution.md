# 高效执行，完整验收

优化目标是减少重复读取、工具返回体积与重复调度，不减少任何阶段、来源证据、确认、源码、Gallery、业务状态或最终验收要求。不设定需要跳过步骤才能满足的时间/token 上限。

## 按需读取与简洁输出

每个阶段进入时读取其必需说明、当前规则与相关源码。已读取且未变的文件沿用本会话理解；新会话、阶段切换或文件变化时重新核对。不要反复打印整个 Skill、全部参考模板、证据历史和无关源码。全文留在文件中，失败时定点读取相关路径和记录。

确定性门禁支持 `--summary`，完整检查、哈希核验和退出状态不变，只减少返回内容：

```bash
node scripts/workflow.mjs status "/目标项目" --stage implementation --summary
node scripts/workflow.mjs status "/目标项目" --stage page --summary
node scripts/verify-project.mjs run "/目标项目" --check static --summary
node scripts/verify-project.mjs run "/目标项目" --check build --summary
node scripts/verify-project.mjs record "/目标项目" --file "/目标项目/deliverables/evidence/visual.json" --summary
node scripts/verify-project.mjs status "/目标项目" --summary
```

摘要保留判定、阻塞、警告、阶段、单项状态、覆盖范围、附件路径和完整 task 状态文件路径；完整历史、输入哈希、命令日志仍由原引擎保存。排查详细证据时去掉 `--summary` 或读取返回的 `stateFile`/附件。不要把摘要当成证据附件替代原始检查。CI 可用相同门禁加此输出参数，退出状态完全一致。

## 减少重复操作

- 批量读取相互独立的规则和源码；依赖上一步结果的操作仍按顺序执行。控制返回范围，完整命令日志保存到文件；失败返回退出状态、关键错误与日志路径。
- 实际参考分析一次形成七项观察与适配映射，分析/约束/范围一次确认。未改变的明确授权不重复询问；来源不足或高影响变化仍须确认。
- 真实浏览器在每个目标尺寸批量验证该尺寸下的适用状态并保存证据，减少反复导航。全部桌面/窄屏、交互、恢复与边界覆盖不变，不用文本读取代替截图或真实操作。
- 不为相同诊断反复运行相同命令。检查器已有当前、通过的真实证据可在同一工作区、同一环境下用于定位进度；最终仍运行完整 status 门禁。修改输入、源码、规则、附件，或者改变环境/依赖/远程数据时重新执行受影响检查。引擎未追踪环境变化，不能仅凭哈希未变就认定有效。CI 在其当前环境重新执行自动检查。
- 源站观察笔记可以用于导航和减少重复探索，但旧截图、旧版本说明或其他项目分析不是本次真实读取与确认。来源/版本/视口和日期必须明确，本次仍核验必需来源与状态；缓存不自动变成当前项目约束。

引擎仅在一次同步 status 调用内部复用相同 task 的当前快照和相同入口的引用图，下次调用重新读取、核验全部输入与附件。没有跨调用通过结果缓存、没有自动补证据、没有降低验收范围。

## 衡量收益

比较相同实际结果的完整/摘要 JSON 字节数、重复文件读取次数和命令耗时；token 数需宿主真实计量，不能把字符缩减冒充总 token 节省。首次完整源码建设与真实验收仍有必要成本。全链路体验效率需后续真实任务计时，不以协议单元测试代替业务或视觉验收。
