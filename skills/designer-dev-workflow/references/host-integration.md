# 宿主中的 Design Harness

## 职责

宿主提供模型、对话、文件编辑、命令执行、浏览器与会话管理。本 Harness 提供设计开发工作流、约束组织、组件与页面复用判断，以及验证和资产维护要求。

使用宿主已有能力完成工作，不建立第二套 Agent 运行循环，也不要求用户管理另一套任务系统。用户可正常对话；这个 Skill 是页面、组件、样式、交互任务的编排入口，其他 Skills 按需调用。

## 项目上下文

按本次任务读取项目规则、开发流程、设计系统索引、相关 tokens/组件/页面与真实实现。路径不明确时使用已有 Adapter 或配置；两者都缺失时先用宿主的文件与搜索能力定位。不要为一次局部修改预读整个设计系统。

0→1 建立满足当前实现与后续复用的最小约束和组件资产；已有项目优先采用实际源码和已有规范。保持已有 token 格式、构建工具和验证方式。

## 工具分级

- 核心：宿主按 Skills 执行，维护项目规范与真实实现，验证适用的视觉、状态和共享影响。
- 可选辅助：CLI 扫描、初始化、确定性检查与诊断；只有它们能减少当前工作时才使用。
- 默认 0→1 交付：使用随 Workflow 安装的 [交付契约与检查器](delivery-gate.md)，由 Agent 生成范围/验收记录并执行，用户不需手工创建 task 或安装 CLI。
- 可选增强：token 导出、显式资产清单和独立 task 管理。用户要求或项目已有配置采用时使用。

没有 CLI、没有托管 token 配置或没有 task 记录，不代表 Harness 不可用。用宿主工具和项目已有测试完成对应检查，在交付记录中清楚区分已验证和未验证。

## 安装后自检

请宿主指出当前可用的 `designer-dev-workflow` Skill 与对应文件路径，并说明本次页面开发会读取哪些项目约束。宿主应实际定位文件后回答；只复述 Skill 名称不能证明完整链路已经生效。

发现技能未加载时核验宿主扫描路径、技能配置、项目指令和当前工作目录，必要时启动新会话。入口提示不是权限控制，也不能覆盖用户或宿主更高优先级要求。

## GUI 选择与阶段执行

GUI 用于浏览和选择起点，不收集业务需求。GUI 保存选择并尝试返回绑定的原 Codex 会话；深链不提交消息，也不启动模型任务。用户在宿主输入需求后，实际读取目标项目选择与需求，通过 `scripts/workflow.mjs read` 记录回执，再执行 [参考分析与阶段契约](reference-analysis.md)。GUI 状态只反映保存与读取，不把它们当作完成分析或开始构建。导航失败时手动返回；交接说明仅作为定位项目的兜底，不要求用户重复粘贴品牌信息。打开目录或安装 Skill 不会自动启动 GUI，纯 Skill 安装也不包含 GUI 服务。

当前工作区安装只更新文件，不证明运行中会话自动热加载。宿主必须实际读取更新后的 Skill；新会话发现、原会话自动返回和新用户回合自动执行应分别验收。正式项目的 CI 应执行交付检查器，缺失、过期或失败必须阻止交付；此检查器不限制宿主的文件写权限。
