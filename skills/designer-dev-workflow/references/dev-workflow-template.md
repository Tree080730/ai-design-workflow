# DEV-WORKFLOW.md 模板

`DEV-WORKFLOW.md` 把通用路径映射到当前项目。它不是所有项目共用的固定正文，应根据 Adapter 中的真实目录、命令和检查方式生成。

```markdown
# 项目分路径开发流程

> 与 RULES.md 配合；强制约束冲突时以 RULES.md 为准，项目事实冲突时以源码和配置为准。

## 通用前置

1. 读取 Adapter、相关规则和现有实现。
2. 明确验收标准和影响范围。
3. 生成技术方案 spec，确认后实现。

## 路径速查

| 路径 | 需求 | 项目落点 | 必做检查 |
|---|---|---|---|
| A | token 变更 | {token-source} | 引用与预览同步 |
| B | 已有组件变更 | {component-dir} | 共享影响与组件文档 |
| C | 新增通用组件 | {component-dir} | 复用论证、索引与状态 |
| D | 新增页面/路由 | {page-dir} / {router} | 可访问、路由和页面文档 |
| E | 新增业务流程 | {feature-dir} | 数据、状态和异常链路 |
| F | 组合需求 | 按层拆分 | 分步验证与增量分诊 |

## 查看设计系统

- 启动命令：{preview-command}
- 预览地址：{preview-url}
- 同步命令：{sync-command}

## 各路径执行结构

每条路径都写清：判定条件 → 读取内容 → 修改落点 → 验证命令 → 文档同步。只记录项目特有差异，不重复通用 Skill 全文。

## 收尾

- 运行、构建和核心交互验证。
- token、组件、页面文档及索引同步。
- 临时预览和路由清理。
- 输出质量检查和交付文档。
```
