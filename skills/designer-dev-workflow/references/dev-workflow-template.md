# DEV-WORKFLOW.md 模板

`DEV-WORKFLOW.md` 把通用路径映射到当前项目。它不是所有项目共用的固定正文，应根据 Adapter 中的真实目录、命令和检查方式生成。

```markdown
# 项目分路径开发流程

> 与 RULES.md 配合；强制约束冲突时以 RULES.md 为准，项目事实冲突时以源码和配置为准。

## 默认 0-1 主线

1. 产品需求与参考 → 确认核心设计约束、技术方案和实现范围。
2. 确认约束 → 落地真实样式、必要组件源码与可运行 Gallery。
3. 真实设计资产 → 实现业务页面与适用状态，验证并交付源码。

只建设设计系统时完成前两阶段；完整业务需求必须继续第三阶段。当前范围已确认时持续推进，不重复确认同一范围；高影响范围变化再确认。组件与模式随实际页面增量补齐。

## 通用前置

1. 读取 Adapter、相关规则和现有实现。
2. 明确验收标准和影响范围。
3. 生成技术方案 spec，确认后实现。

## 补充路径速查

| 路径 | 需求 | 项目落点 | 必做检查 |
|---|---|---|---|
| A | token 变更 | {token-source} | 引用与预览同步 |
| B | 已有组件变更 | {component-dir} | 共享影响与组件文档 |
| C | 新增通用组件 | {component-dir} | 复用论证、索引与状态 |
| D | 新增页面/路由 | {page-dir} / {router} | 可访问、路由和页面文档 |
| E | 新增业务流程 | {feature-dir} | 数据、状态和异常链路 |
| F | 组合需求 | 按层拆分 | 分步验证与增量分诊 |

## 最小 0-1 启动

- 最小设计系统包含可运行 Gallery，先展示真实 tokens，已有组件与模式随实现登记。
- 尚无资产的分区明确显示未登记，不虚构组件；首轮交付同步当前资产。
- `init` 只生成模板与索引，宿主负责按项目技术栈实现展示入口。

## 查看设计系统

- 启动命令：{preview-command}
- 预览地址：{preview-url}
- 同步命令：{sync-command}

## 各路径执行结构

每条路径都写清：判定条件 → 读取内容 → 修改落点 → 验证命令 → 文档同步。只记录项目特有差异，不重复通用 Skill 全文。

## 收尾

- 核验必需源码已在目标项目实现并接入运行入口；文档、索引和临时预览不能代替代码。
- 交付源码路径、真实引用与安装/运行命令；必需代码缺失记为未完成，未执行的运行验证如实记录。

- 运行、构建和核心交互验证。
- 路由、异步恢复、跨页状态、持久化或可逆操作变化时，复用项目现有 E2E 验证完整状态闭环；静态样式和无状态局部调整不强制 E2E。
- 测试包与浏览器运行时分别核验；运行时二进制和报告不进入仓库。
- token、组件、页面文档及索引同步。
- 临时 proposal 预览和路由清理；长期 Gallery 保留。
- 0-1 交付核验 Gallery 入口可运行、资产引用与索引同步；缺失或不可运行记录为未完成。
- 输出质量检查和交付文档。
```
