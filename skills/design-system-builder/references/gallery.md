# Design System Gallery 实施契约

## 目的与接入

将已有设计约束变成可看、可操作、可核验的持续入口。Gallery 属于目标项目，不是 Harness 独立产品界面。先发现现有 Storybook、文档站、路由与组件资产；沿用项目框架、token 管线和测试方式。用户要求 Gallery 或设计系统系统化建设时交付；普通业务修改只同步受影响条目，不重建整站。

没有现有入口时，建立开发专用页面或独立构建入口。入口、启动命令、生产包含/排除方式写入设计系统 README 与 Adapter；不得自动接入公开业务导航。样例没有真实业务后端，正式接入时不使用生产 API、真实用户数据或写入操作。

## 必需内容

| 区域 | 展示与来源 |
|---|---|
| Foundations | 真实颜色、字体、间距、圆角，以及已有阴影/动效；标注 token 名、来源与别名。缺失规则明确标记，不用模板默认值填充 |
| Components | 挂载真实组件，展示现有变体与默认、禁用、加载、错误等适用状态；说明用途、使用边界、源码与规范位置 |
| Patterns | 真实组件组合的布局或页面模式，注明模拟数据与响应式行为；不复制业务页面实现来冒充共享模式 |
| Navigation | Foundations / Components / Patterns 分区，稳定锚点，桌面和窄屏可访问 |
| Traceability | 每项稳定 id、源码与规范引用；candidate、待补齐、未验证如实标记 |

主题、密度和语言只展示项目实际支持的范围。存在主题时验证主题切换与真实 token 一致。条目可以显示仓库相对路径；能够使用文档站或源码浏览链接时提供可点击链接，不能把磁盘路径假装成 HTTP 地址。

## 模板使用

React 模板 `assets/DesignSystemGallery.tsx` 接收 token 条目和 ReactNode 展示项；`assets/gallery.css` 只提供布局样式，使用示例 token 名，接入时映射到项目语义 tokens。条目应从现有机器源读取或由工具链生成；不得维护第二份手写 token 数值。色块、间距和圆角使用真实 CSS 变量。组件与模式通过项目 imports 实例化，不在 Gallery 内复刻样式或实现。

该模板是起点，不能自动发现任何框架的所有组件。Agent 根据实际 props、状态和设计资产登记条目。新增/改名/删除 token、组件和模式时同步展示、索引及映射。缺失文档先明确标记并按项目生命周期补齐。

仓库可运行示例：`examples/react-vite`。运行 `npm ci`、`npm run dev`，根页面展示 Gallery；示例根入口只用于演示，不建议替代真实项目业务入口。

## 验收与维护

1. 运行项目构建与类型检查，核验条目来源和文档路径，不以静态零问题代替浏览器检查。
2. 在代表性桌面与窄屏实际渲染；检查导航锚点、对齐、换行、溢出、可见焦点及控件名称。
3. 操作展示中的本地交互，验证适用的错误恢复、禁用和加载状态；展示不能触发真实业务副作用。
4. 核验 Gallery 与实际产品使用同一 token 与组件来源；引用过期、状态缺失或不可运行不得声称通过。
5. 记录实际入口、视口、操作与结果。缺少浏览器能力时明确未验证项。

Gallery 不是一张组件拼图或静态截图，也不意味着全部产品页面已经通过验证。持续 Gallery 保留；方案确认用临时预览照常清理。
