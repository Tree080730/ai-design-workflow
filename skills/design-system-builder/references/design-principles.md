# 设计原则模板

设计原则用于解决取舍，不是形容词列表。每条原则都应能判断一个具体方案是否更合适。

## 原则结构

```markdown
## {原则名称}

- 定义：这条原则要求什么。
- 用户价值：解决什么真实问题。
- 应该：可观察的正向行为。
- 避免：可观察的反向行为。
- 冲突时：与其他原则冲突时如何排序。
- 验证：通过什么界面或指标检查。
```

## 建议维度

- 清晰：信息层级和下一步是否明确。
- 一致：同一概念是否使用相同组件、文案和行为。
- 效率：高频任务是否减少不必要步骤。
- 容错：错误是否可预防、解释和恢复。
- 包容：键盘、读屏、对比度和触控目标是否可用。
- 品牌：品牌表达是否服务内容，而非压过任务。

## 冲突处理

先满足可用性和可访问性，再处理效率和一致性，最后处理装饰性表达。若产品目标要求不同排序，应明确记录原因和适用范围。

## 反例

“现代、简洁、高级”不能直接指导实现；需要转化为可验证约束，例如信息层级数量、默认密度、色彩使用范围或动效时长边界。
