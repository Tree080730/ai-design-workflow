# Rules Governance

识别规则漂移并提出可审核的修正建议。扫描结果只能生成候选变更，未经用户确认不自动修改长期规则。

## 模式

- 快速模式：只扫描本次变更文件，适合交付前检查。
- 完整模式：扫描全部源码、规则和设计系统，适合用户明确要求巡检或架构节点检查。

## 1. 探测事实来源

定位：token 源、`RULES.md`、`DEV-WORKFLOW.md`、Project Adapter、设计系统目录、源码目录、构建产物和第三方覆盖目录。路径不明确时先读取 Adapter；仍存在多个候选再询问。

## 2. Token 与硬编码检查

按 [Token 扫描规则](references/token-scanning-rules.md) 检查颜色、字体、间距、圆角、阴影、层级和动效值。

分类：

- P0：绕过既有语义 token，可能破坏主题或一致性。
- P1：可映射到现有 token 的非标值。
- P2：合理但尚未 token 化的重复值，建议评估沉淀。
- 豁免：token 定义、第三方覆盖、插图几何或有明确注释的特殊值。

不根据数值“看起来相近”就自动替换；先确认语义相同。

## 3. 文档覆盖检查

对比源码组件/页面与 `design-system/components`、`design-system/pages` 及其索引。识别：缺少文档、文档指向不存在源码、重命名未同步和预览未登记。

工具组件、测试夹具和临时预览可以豁免，但必须说明判断依据。

## 4. 规则边界检查

判断规则应该落在哪里：

| 内容 | 目标 |
|---|---|
| 跨模块强制约束、工程卡点 | `RULES.md` |
| 项目路径、命令和工具映射 | Project Adapter / `DEV-WORKFLOW.md` |
| token 数值和视觉细节 | `design-system/` |
| 单组件状态与行为 | 对应组件文档 |
| 单次需求决策 | 本次 spec 或交付文档 |

识别重复、冲突、过期和被误写为长期规则的一次性要求。

## 5. 输出报告

```markdown
# 规则巡检报告

- 模式：快速 / 完整
- 扫描范围：
- 事实来源：

## Token 合规
| 级别 | 文件:行 | 当前值 | 候选 token | 判断依据 |

## 文档覆盖
| 源码 | 文档 | 状态 | 建议 |

## 规则候选变更
| 动作 | 目标文件 | 内容摘要 | 来源 | 影响 |

## 无需操作
- 已覆盖或合理豁免项

## 未验证风险
- 
```

## 6. 确认后写入

按目标文件分组请求确认。写入时保持单一事实来源：RULES 只保留索引和强制约束，不复制 token 值或组件全文。完成后重跑相关检查，报告已修复、仍存在和新发现项。

## 边界

- 不把每个代码风格偏好升级为项目规则。
- 不在审计任务中擅自重构业务代码。
- 不扫描构建产物、依赖目录或生成文件。
- 不因一次扫描没有命中就删除现有规则；先确认其历史和适用范围。
