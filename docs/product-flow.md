# 产品定位与用户链路

本文是当前产品定位、职责、用户链路和能力状态的统一说明。操作命令见 [GUI 使用说明](design-builder.md)，宿主安装见 [接入说明](host-integration.md)，阶段执行要求见 [参考分析契约](../skills/designer-dev-workflow/references/reference-analysis.md)。带日期的验收与方案文档记录当时状态，不代替当前使用指南。

## 定位与职责

本项目运行在 Codex 等成熟 coding Agent 中，帮助用户从设计起点建立项目自己的设计系统、Gallery 和业务页面，并持续迭代。

- GUI 提供选择与浏览：扩充用户的视觉视角，先选择可选的组件基础，再选择可选的品牌官网、用户网页或图片参考；不收集业务需求，不承担对话或模型执行。
- 宿主负责用户需求对话、模型、工具、权限、会话及实际实现。用户在原会话正常输入需求和修改意见。
- Workflow 与 Skills 组织输入读取、真实来源分析、业务适配、合并确认、共享资产实现、验证与维护。
- 项目规则、tokens、主题和共享组件承载持续约束；阶段检查与项目 CI 检查声明的交付条件。

GUI 展示的图片与编辑观察方向用于浏览和启发，不能视为宿主已完成来源分析，也不是品牌官方的完整设计系统。

## 用户体验目标与当前路径

期望的首次体验：获取项目 → 在 Codex 打开 → GUI 出现 → 选择起点 → 返回原会话 → 输入业务需求 → 分析与适配约束合并确认一次 → DS/Gallery → 业务页面 → 验证与持续迭代。

当前可执行路径：安装 Skills 到目标项目 → 在宿主打开目标项目并核验加载 → 从 Harness 仓库启动 GUI 并打开地址 → 保存选择 → 尝试返回明确绑定的原会话 → 用户输入需求 → 宿主读取选择并按阶段契约执行。

仅打开项目目录不会自动启动 GUI。已提供受信任 SessionStart Hook 的启动入口和实例恢复机制（见 [启动说明](gui-startup.md)），原生触发已在隔离项目验收通过，正式工作区原生新会话启动与GUI自动展示已通过用户实测及日志核对，内置浏览器同会话衔接通过；深链导航未独立验证；会话返回链接只尝试导航，不预填或提交消息。导航失败时用户手动返回原会话，选择仍保存在目标项目。可复制的交接说明仅是帮助宿主定位项目的兜底，不是日常必需步骤。

已有选择的项目应围绕当前项目资产继续工作，需要调整起点时再回 GUI；启动器根据有效选择文件区分首次与再次使用；仅打开目录仍不构成启动事件。纯 Skill 使用仍兼容没有 GUI 选择文件的项目；没有选择文件不等于用户明确选择“不使用预设”。

## 组件底座与视觉参考

| 选择 | 宿主如何处理 | 不应推断的能力 |
|---|---|---|
| 开源组件基础（components） | 核验官方来源、工程兼容性、实际版本、所需能力、主题及许可，形成项目适配规则并接入真实组件 | 点击选择即已安装或适合全部场景 |
| 品牌官网参考（reference） | 真实观察页面，区分观察、推断、业务适配与缺口，形成项目视觉和交互规则 | 官网外观就是完整组件库；截图或 URL 已完成分析 |
| 组件＋参考（combined） | 同时执行组件七项和参考七项分析，确认底座与视觉适配 | 只分析其中一项或因视觉换参考而自动换库 |
| 不使用预设（custom） | 基于用户需求和已有资产建立项目自己的体系，继续同一工作流 | 沿用历史品牌或跳过设计系统与验证 |

发现列表有“开源组件”和“设计参考”两个步骤，无“全部”tab；设计参考仅收录品牌官网。Apple HIG 仅为旧选择兼容保留，不是当前发现列表中的 Apple 官网参考。两个入口现在是连续步骤：组件可跳过，随后参考可跳过；最终一起保存。支持组合品牌官网、自定义 URL 和图片。新版输入契约见 [设计基础](../skills/designer-dev-workflow/references/design-basis.md)。组合输入与图片的程序及 GUI 验收不替代完整项目构建验收。

## 从启发到约束

选择保存 → 宿主实际读取最新选择与本次需求 → 获取来源证据 → 分析并说明适配取舍 → 用户合并确认 → 项目规则/token/组件 → Gallery 与页面消费 → 实际验证。

选择本身不等于批准全部品牌风格或实施范围。来源无法观察时暂停依赖步骤，请用户确认替换来源或调整要求；不能自行改用另一品牌或将推测写成官方规则。用户确认后，Agent 继续在授权范围内完成实现。

Skill 是执行指引；阶段检查核验已声明证据、文件摘要、规则映射和前置步骤；共享源码承载工程约束；视觉与交互符合程度仍需真实审查。检查器不能独立认证截图来源、人工判断或确认身份，也不限制宿主直接写文件。只有项目 CI 实际调用检查器时，其退出状态才构成交付门禁。

后续迭代复用已确认的项目规则和真实资产。受影响来源、约束或源码变化须按现有契约重验；高影响范围变化重新确认。更细的增量失效与检查范围机制仍待完善，本文不改变现有阶段检查行为。
