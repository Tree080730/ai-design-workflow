# 全链路一致性修复方案（已确认实施）

> 历史方案/验收记录：保留当时的环境、实现与测试边界，不作为当前操作指南。当前职责、链路和能力状态以 [产品链路](product-flow.md) 为准，实际操作见 [GUI 使用说明](design-builder.md)。

日期：2026-10-06。用户要求全面补齐流程缺口，并在需要确认时先确认。用户已确认三项决策：继续 Codex 宿主；证据不足暂停并确认；分析与适配约束合并确认一次。本文仍是范围方案，不是实现完成记录。

## 方案制定时的证据与缺口

- GUI 能保存选择；当前宿主已实际读取隔离项目文件。桌面自动返回和后续新用户回合自动加载仍未独立验证。
- reference 输入保存 URL 与观察方向；尚无强制的逐项参考分析契约。Apple 验收只读取网页文本，未完成实时视觉/交互/响应式观察。
- 设计约束要求已有，但交付检查器主要检查源码、引用与登记证据，不能阻止未完成分析就开始实现。
- 父目录已安装 Skill 与仓库源 Skill 不同。部署更新、版本一致性和宿主实际加载需要区分。
- GUI 有“宿主会读取”的确定性提示，却没有确认读取回执；深链打开不等于消息提交或流程执行。
- 既有自动测试覆盖安装、GUI 持久化与交付契约，缺少选择 → 读取 → 分析 → 确认 → DS/Gallery → 页面 → 验收的完整正向与故障用例。

## 拟实施范围

1. 输入交接：规范选择文件校验、明确项目绑定与选择摘要；宿主读取最新内容后记录实际读取时间、输入摘要与版本。不以 GUI 保存或链接跳转代替宿主读取。换选导致相关分析和后续证据失效。
2. 三类输入分支：reference 分析真实页面；components 核对真实官方组件、版本、主题和所需能力；custom 按业务约束建立项目自己的体系。不要求无关步骤，不用另一分支冒充完成。
3. 参考分析：逐项记录视觉层级、颜色与文字、布局几何、组件/状态、交互/动效、桌面与窄屏。每项区分观察、推断、项目适配和未观察，附来源/时间/本地证据；GUI 展示截图不是已完成分析。证据覆盖依本次目标，动态/登录不可见项如实记录。
4. 分析到设计的映射：来源观察 → 适配理由 → 项目规则/token/组件 → 页面消费 → 验收。禁止推断冒充官方数值，禁止缺失规则由不透明默认值补齐。
5. 阶段检查：输入核验 → 参考/基础分析 → 用户确认约束与范围 → DS/Gallery → 业务页 → 实际检查与交付。独立阶段状态及程序条件；缺项、过期、错误项目、未确认和不可验证分别返回阻塞，保留恢复入口。已有项目局部任务复用真实资产，以可追溯理由判断适用范围，不重复建立整套底座。
6. 单一事实来源：先修改仓库源 Skills 与 CLI 检查实现，再通过既有同步脚本/安装器同步发布副本；检查同步一致性，不覆盖用户改动。确认后更新本工作区受管理安装，明确运行中会话不等于自动热加载。
7. 用户体验与证据：GUI 区分“已保存”“等待宿主读取”“已读取”，不可发送时不显示开始执行成功。新增完整链路测试与缺失/过期/拒绝/失败恢复测试；重新真实验收 reference/components/custom 的适用链路。自动测试、Agent 观察和真实宿主新回合验证分开报告；无真实宿主证据不宣称完全跑通。

## 不变边界

保留现有宿主执行架构、项目资产和 token 管线。无明确授权不新增独立 Agent、不修改宿主权限、无公开受支持接口不猜测投递协议。本轮不改用户业务选择、不创建新会话、不自动发送消息。

Skill 是模型执行指引；程序检查和 CI 能阻止已登记的不完整交付，但不能证明所有语义判断正确，也不能限制具备写权限的 Agent 修改规则。目标是可验证、可阻塞、可追溯的严格链路，不承诺无法证明的绝对保证。

## 已确认的决策记录

- 维持当前 Codex 宿主/共享文件架构，还是改为独立执行运行时？推荐前者。
- 参考页面无法实际观察时，停止依赖该证据的阶段并请用户替换来源/确认调整，还是允许自动生成候选风格？推荐停止依赖阶段，继续无依赖检查。
- 正常确认节奏：建议完整参考分析及适配约束后确认一次；后续按已确认范围执行，只有高影响变化再次确认。也可要求分析和 DS 预览分别确认。

以上决策已由用户确认；Skill 安装冲突另经用户明确批准完整备份并合并。实施与验收结果见 [一致性验收记录](workflow-consistency-acceptance.md)。此前一次隔离测试仍保留其未验证状态，不追补虚构证据。
